# ForgeSEO pilot implementation contracts

Standalone application, no imports or runtime connections to Business Optimizer or legacy ForgeSEO. Never read/copy .env files into code or logs. Use apply_patch for all authored files. Preserve other agents' changes. No live site writes or paid API calls in implementation tests.

## Shared stack and ownership

Python 3.12+, FastAPI, SQLAlchemy 2, PostgreSQL production / isolated SQLite tests, Celery/RabbitMQ. React/TypeScript/Vite UI. Imports start `app`. UTC naive datetimes in database; API ISO timestamps. UUID hex string ids except Event integer monotonically increasing id. All JSON values updated by assigning a new dict/list. Tests use pytest and httpx mock transports.

Foundation agent owns app/config.py, app/db.py, app/models.py, app/auth.py, app/policies.py, app/budgets.py, tests/test_foundation.py, alembic/** and alembic.ini. Frontend agent owns frontend/**. Connector agent owns app/connectors/**, wordpress/**, tests/test_connectors.py. Intelligence agent owns app/intelligence/**, tests/test_intelligence.py. Main integrator owns app/main.py, app/api.py, app/workflows.py, app/worker.py, app/scheduler.py, app/operations.py, deployment files and integration tests. Do not edit another scope.

SQLAlchemy declarative Base; model constructor fields are exactly below, sensible defaults. Common id string default uuid4().hex and created_at datetime default now unless stated.

- Team: id,name,created_at.
- Membership: id,team_id,user_id,role (owner/editor/viewer), unique(team_id,user_id).
- Session: id,user_id,token_hash(unique),csrf_token,expires_at,created_at.
- Site: id,team_id,name,origin,timezone(default America/Chicago),language(default en),facts(JSON dict),paused(default true),created_at.
- Connection: id,site_id,kind,encrypted_credentials(Text),status(default needs_connection),capabilities(JSON dict),checked_at(nullable),created_at; unique(site_id,kind).
- Policy: id,site_id,version(int),settings(JSON dict),created_by(user id nullable),created_at; unique(site_id,version). Append-only, no in-place updates.
- Page: id,site_id,resource_key,url,title,resource_type(default posts),source(JSON dict),signals(JSON dict),source_hash(string),enrolled(bool false),managed(bool false),last_seen_at(datetime),created_at; unique(site_id,resource_key).
- Finding: id,site_id,page_id(nullable),key(string),code,severity,title,details(JSON dict),status(default open),first_seen_at,last_seen_at,resolved_at(nullable),recurrence_count(int 0); unique(site_id,key).

- Article: id,site_id,title,slug,body(Text default empty),status(default planned),brief(JSON dict),checks(JSON dict),sources(JSON list),author_id(nullable string WP author id),scheduled_at(nullable datetime),remote_id(nullable string),managed(default true),created_at,updated_at.

- Publication: id,site_id,article_id(nullable),candidate_id(nullable),operation_key(unique),status(default pending),policy_version(int),snapshot(JSON dict),result(JSON dict),remote_id(nullable),created_at,updated_at.

- Incident: id,site_id,key,kind,severity,title,status(default open),details(JSON dict),failure_count(int 0),first_seen_at,last_seen_at,resolved_at(nullable); unique(site_id,key).

- CostReservation: id,site_id,account_id,operation_key(unique),estimated_cents,actual_cents(nullable),status(default reserved),created_at.
- Event: id integer autoincrement,site_id(nullable),team_id,kind,message,data(JSON dict),created_at.
- Heartbeat: name(string PK),last_seen_at,details(JSON dict).

Use ForeignKeys and relationships only when needed. Define indexes for site/status/time queries.

## Foundation APIs imported by main

- config.settings: DATABASE_URL, BROKER_URL, ENCRYPTION_KEY, COOKIE_SECURE(bool), GLOBAL_PAUSE(bool default true), PUBLIC_URL, BOOTSTRAP_TOKEN, ARTIFACT_ROOT. Settings loaded from environment via pydantic-settings; no embedded secrets. Development database default sqlite:///./data/forgeseo.db. A fresh deployment must provide `BOOTSTRAP_TOKEN`; the empty local default fails closed.
- db.get_db() yields Session; db.SessionLocal; db.engine; db.init_db() only local dev/tests (production migrations).
- auth.router APIRouter prefix `/api/v1`, endpoints GET /auth/status -> {initialized}, POST /auth/bootstrap {email,password,name,team_name} with deployment-only `X-ForgeSEO-Bootstrap-Token` header, POST /auth/login {email,password}, GET /auth/me, POST /auth/logout; GET /team, POST /team/members {email,name,password,role}, PATCH /team/members/{user_id} {role}, and DELETE /team/members/{user_id}. The member lifecycle routes are owner-only, scoped to the selected team, reject self-demotion/self-removal and removal or demotion that would leave no owner, and invalidate sessions for a removed membership. Cookie session `forge_session` HttpOnly and CSRF check X-CSRF-Token for all authenticated unsafe requests. /auth/me -> {user:{id,email,name},team:{id,name},role,csrf_token}. bootstrap first-owner only atomically; login/bootstrap return same shape and cookie. Explicit same-origin validation; secure cookies configurable for local HTTP. The bootstrap token is never returned or accepted for routine logged-in requests.
- auth.require_user dependency -> context object/dict with user_id,team_id,role; auth.require_role(context,*roles); auth.require_site(db,context,site_id)->Site (team ownership validated, 404 cross-team). Main FastAPI mounts router. csrf may be enforced in require_user.
- policies.DEFAULT_POLICY: {enabled:false,allowed_actions:[metadata],protected_paths:[/,/contact*,/privacy*,/terms*,/checkout*,/cart*,/my-account*],posts_per_week:2,refreshes_per_week:1,monthly_budget_cents:30000,tracked_keywords:[],competitors:[],tracked_questions:[],publish_days:[1,4],author_id:null}. allowed_actions values metadata,publish,refresh,store_editorial,links,alt_text. Max keywords25, competitors3, questions20 unless explicitly settings support raising bounded values. Persist policy via policies.create_policy(db,site,user_id,settings_dict)->Policy and policies.current_policy(db,site_id)->Policy|None.
- policies.evaluate_policy(site,policy,action,page=None,global_pause=False)->list[str] blockers; checks pause, enabled, allowed actions, protected paths, body enrollment. Publishing checks business facts and author. Editor can't change policies/credentials/members.
- budgets.reserve(db,site_id,operation_key,estimated_cents,limit_cents=30000)->CostReservation; budgets.settle(db,reservation_id,actual_cents); budgets.release(db,reservation_id). Concurrency safe atomic reserve; unknown/negative pricing denied; SQLite tests prove budget accounting, Postgres locks in production. Errors ValueError.

## Connector interface (connector agent implements)

app.connectors.wordpress.WordPressClient(origin,credentials:dict,transport=None): async context manager, async discover()->dict capabilities, async inventory()->list[dict], async read(resource_key)->dict, async create_draft(article:dict,operation_key:str)->dict, async publish(remote_id:str,expected_hash:str|None=None,operation_key:str|None=None)->dict, async update(resource_key:str,changes:dict,expected_hash:str,operation_key:str|None=None)->dict, async restore(resource_key:str,snapshot:dict,expected_hash:str|None=None,operation_key:str|None=None)->dict. Optional operation keys are request-scoped correlation markers for the signed notification feedback-loop guard; they never grant authorization. Returned records normalized {resource_key,resource_type,id,url,title,body,status,metadata,source_hash,raw}; hashes stable over editorial source, exclude volatile hints. Content read authenticated. Credentials never logged, SSRF protection rejects private IPs/redirect authority changes; mock transports allow example.test tests. Lost create response reconciles known deterministic slug/operation marker; never blind retries. Typed errors ConnectorError, AmbiguousOutcome, SourceConflict. Unsupported fields fail closed. Protected commercial/builder fields never written.

app.connectors.woocommerce.WooCommerceClient same construction/context manager; inventory(), read(resource_key), update(resource_key,changes,expected_hash), restore(...), discover(). Only products/category editorial fields are writable through WooCommerce REST. Product or product-category SEO title/description writes are additionally allowed only when the matching narrow ForgeSEO route advertises both authenticated read and mutation methods, and are re-read after writing; each resource type is gated independently. Reject price/stock/SKU/etc recursively. WP/Woo separate credentials.

app.connectors.security exports encrypt_credentials(payload,master_key) and decrypt_credentials(ciphertext,master_key), plus async/public URL safety helper as needed. Reuse reviewed legacy encryption and URL validation concepts with license attribution, no runtime dependency.

Optional plugin provides capabilities and operation mapping, signed outgoing events, least-privilege SEO field control through documented namespaced REST. Include PHP tests or static validation if PHP unavailable; disclose.

- app.intelligence.content.plan_topics(facts,pages,keywords=None,products=None,origin=None,research_inputs=None)->list[dict] four-week max8 briefs with bounded, provenance-preserving search/competitor observation context, review-only internal-link opportunities, and Article structured-data prerequisites derived from stored same-origin pages and explicit facts; observations may inform a topic but never authorize publication or become unsupported claims; no fake research or generated copy fallback. content.check_article(article:dict,facts:dict,pages:list=None)->dict {passed:bool,blockers:list,warnings:list}; validate provenance and known facts, complete titles, markup, duplicates, sources, author, and explicit image provenance. Owner-provided images require confirmation; licensed images require attribution and licence; generated illustrations require disclosure and a non-real-product/premises assertion. content.generate_article(brief,facts,provider_config:dict,transport=None)->dict async with explicit missing connection/error, no live calls during tests. Provider endpoint/model configured, provenance/source preservation, no model authority to publish; function never approves.
- app.intelligence.visibility: async collect(kind,credentials,settings_dict,transport=None)->dict {kind,source,observed_at,data,cost_cents}. Support gsc,ga4,dataforseo,ai_sample,pagespeed using real API contracts with mocked tests. Handle unavailable/unknown pricing, errors, refresh OAuth tokens if needed without leaking. No fabricated metrics. Successful AI samples preserve provider, model, question, locale, answer, citations, ranking type, and the observed timestamp when supplied. GA4 accepts bounded non-secret report dimensions, metrics, and optional conversion event names; conversion names become a read-only eventName filter and never create or change Analytics events. DataForSEO SERP requests batch at most 25 bounded tracked keywords and require known pricing before paid HTTP. Its bounded `competitors` mode uses the policy target plus at most three public competitor domains, requires a configured location and known pricing, and returns a provider-scoped competitor observation with actual cost/task-error handling. The scheduler queues that mode separately from normal DataForSEO visibility work only when policy competitors are configured; workflow mode overrides accept only this bounded value and always use the policy list. Provide validate_measurement_import(payload)->list[dict], preserving the declared measurement kind and source provenance for AI samples, citations, referrals, technical observations, backlink observations, business-listing observations, and competitor observations. Backlink/listing imports accept only bounded scalar fields and public HTTP URLs, explicitly classify them as non-ranking recommendation evidence, and reject ranking claims. Competitor imports may preserve a provider-reported position only under an explicit competitor/query/provider/date scope; they are not universal ranking scores or write authorization. Every imported envelope is recursively inspected before persistence and rejects credential-shaped keys or over-deep/over-large payloads without storing them; ordinary fields such as token_count and authorization_class remain valid. Distinguish AI samples from consumer rankings.

## HTTP contract for frontend (main implements)

All under /api/v1, same-origin cookies, JSON, error {detail:string|object}, GET lists {items:[],total}. Unsafe requests X-CSRF-Token from auth. IDs opaque strings.

- GET/POST /sites; POST {name,origin,timezone,language,facts}. GET/PATCH /sites/{id}; PATCH {name,facts,paused,...}. facts includes business_name,audience,locations,services,products,authors,confirmed_sources and optional language/brand tone.
- GET /sites/{id}/overview -> {site,counts:{pages,open_findings,pending_candidates,published_articles,open_incidents},monitoring:{status,last_seen_at},budget:{limit_cents,spent_cents,reserved_cents},recent_events:[],coverage:{status,last_audit_at},connections:[]}.
- GET /sites/{id}/connections -> list envelope; PUT /sites/{id}/connections/{kind} {credentials:{},settings:{}} encrypted, only safe fields returned; GA4 settings may include bounded non-secret property/report dimensions, metrics, and conversion-event names; POST .../{kind}/test -> Job (Google gsc/ga4 tests perform a read-only provider request and persist only a bounded verification summary; paid sources are not charged implicitly); DELETE .../{kind} revoke.
- GET/PUT /sites/{id}/policy -> {id,version,settings}; PUT {settings:{...}}. GET /sites/{id}/pages and PATCH .../pages/{pageid} {enrolled:bool}.
- GET /sites/{id}/findings, /candidates; POST .../candidates/{candidateid}/decision {decision:approve|reject}; POST .../candidates/{candidateid}/execute -> Job (policies still apply).
- POST /sites/{id}/jobs {kind:audit|inventory|plan|generate|publish|availability|visibility|refresh|full_cycle,payload:{},idempotency_key:optional}; GET /sites/{id}/jobs returns a stable `{items,total}` operational-history envelope ordered newest-first by `created_at` (with opaque ID tie-breaking), and collection items omit `idempotency_key` and credential-storage fields; GET /sites/{id}/jobs/{jobid} retains the existing detail shape while redacting credential-shaped fields nested in payload/result at the browser API boundary. `full_cycle` is a bounded read-only orchestration of availability, verified WordPress inventory when connected, public audit, content planning, and enrolled refresh evaluation. Its result reports stage states and next actions; publishing, metadata writes, paid visibility, and other remote mutations remain separate policy-gated workflows.
- Scheduler-created write jobs carry non-secret authorization provenance in their durable payload: `authorization:{type:"policy",action:"publish",policy_version:<version>}` and the matching root `policy_version`. This records which site policy authorized enqueueing; the worker must still re-evaluate the current policy, pauses, permissions, freshness, budget, and remote state before any write.
- GET/POST /sites/{id}/articles; POST {title,brief,sources,author_id}; GET/PATCH /sites/{id}/articles/{id} {title,body,brief,sources,author_id,scheduled_at}; GET .../{id}/revisions; POST .../{id}/check; POST .../{id}/schedule {scheduled_at}; POST .../{id}/publish ->Job; POST .../{id}/rollback ->Job.
- GET /sites/{id}/products (Page product records), /incidents, /activity, /measurements, /publications -> list envelopes. Activity, overview, weekly-report, and SSE responses expose only an allowlisted scalar event summary; arbitrary event payloads, credentials, provider responses, and raw HTML never cross the browser boundary. Browser-facing Page source/signals, Finding/Candidate/Incident details, Article brief/sources, Publication snapshot/result, and Measurement data retain useful fields while recursively redacting credential-shaped nested values. POST /sites/{id}/measurements/import {items:[]} validated measurement observations with explicit kind/source provenance. GET /sites/{id}/reports/weekly -> JSON; ?format=csv -> CSV download. GET /sites/{id}/events is an authenticated SSE stream with Last-Event-ID replay: named `activity` events carry the safe event summary, while named `progress` events carry only safe bounded job status/stage fields. Both event names share the same site-scoped monotonic cursor.
- GET/PATCH /settings -> {global_pause,...}; owner only patch emergency control persisted.

Pagination limit default50/max200 offset >=0. No demo data injected into live flows. UI task status must reflect network/job truth. UI labels: Automatic, Needs review, Needs connection, Unsupported. Connection kinds wordpress,woocommerce,gsc,ga4,dataforseo,ai,pagespeed,smtp. Missing secrets shown as needs connection; don't ask for all credentials to onboard.
